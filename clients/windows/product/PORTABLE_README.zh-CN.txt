Oracle Proxy 0.3.0-rc13 · Windows 10/11 x64 便携验收包

本包尚未通过真实 UU 会话和物理重启验收，应用未进行发行者签名，不是正式版。
请仅在可本地操作、断网后能自行恢复的测试电脑使用。
当前服务器未启用 IPv6 出口：IPv6 被阻断，IPv4、TCP、UDP 与 DNS 经 WireGuard。

使用步骤
1. 将完整 ZIP 解压到本地文件夹，保留三个程序文件在一起，不要直接在 ZIP 内运行。
2. 打开 OracleProxy.exe，点击“安装 / 升级服务”并确认 UAC。无需安装 .NET、WireSock、WireGuard GUI 或 FlClash。
3. 使用管理员分配的账号密码登录，点击连接。设备自动登记，私钥只保存在本机 SYSTEM 加密存储。
4. 日常操作无需管理员权限。界面分为“当前连接”“账号与用量”“诊断与测试”，左侧导航可跳转；小窗口可纵向滚动。
   连接区显示本次验证的出口 IP、实际协议、隧道 HTTP 延迟及本机 VPN 网卡的上下行速率。速率约每秒更新，首次采样或核心重启时暂不显示数值；它与服务器统计的月用量口径不同。
   账号区集中显示月用量进度、已用/总额/剩余、到期日、已登记设备数及登录/退出。设备数是已登记数量，不表示当前在线数量。
5. 点击“断开并恢复直连”恢复直连并保留快速重连；点击“断开并退出”或正常关闭窗口会停止核心、恢复直连后退出界面。系统服务空闲待命，账号登录保留。界面意外崩溃、被强制结束或系统关机不会自动取消保护。

连接排障
若显示“已保护 · 等待连接”，说明尚未确认 Oracle 出口，不代表连接成功。
可点击“断开并恢复直连”，失败时使用“恢复直连（UAC）”；不要关闭系统防火墙。
“连接诊断”显示失败阶段、固定核心阶段、异常类别和数值/枚举错误码，不导出原始日志或配置。
诊断不含账号、密码、令牌和私钥；可复制给维护者。
首次出口探测暂时失败时，若核心与受保护的隧道授权仍有效，会保留加密隧道继续重试，避免反复中断握手。
自动模式首选原生 WireGuard UDP 51820（可备用 UDP443），随后尝试 QUIC/HTTP3 UDP8443，最后才用 HTTPS/TLS443 兜底；也可选择首选 UDP 或 QUIC/HTTP3。QUIC 仅在服务器公网验收通过并启用后使用；HTTPS/TLS 仅作受限网络兜底。所有通道都保留 WireGuard 加密、身份验证与用量策略。
HTTPS 成功时显示“已连接 Oracle · HTTPS”，诊断中的 transport 为 wireguard-https。失败时保持保护，不恢复普通流量直连。
出口未通过验证前仍显示“已保护 · 等待连接”；这不是连接成功提示。诊断包含本设备的服务器握手时间和流量计数。

UU 远程
程序根据安装记录和运行进程自动发现 UU，校验网易数字签名及文件/目录权限，不依赖盘符或固定安装路径。
已发现但不安全的安装会阻止连接，请先处理界面提示。真实登录会话在 VPN 故障时能否保持在线尚未验收。
请先在本机测试，再用于只能通过 UU 访问的电脑。
如无法连接：在断开状态点击“重新识别 UU”，再点击“UU 检查详情”。
详情只显示候选数量、核验原因和路径，不含账号密码、密钥或令牌；可复制给维护者定位。
不要先修改 UU 或父目录权限、关闭防火墙，或进行结束进程/断网/重启测试。
本版保留原有签名及目录安全检查，并新增“修复 UU 权限（UAC）”和“恢复 UU 权限（UAC）”。
仅在可本地操作的测试机、VPN 断开时使用修复；先核对提升权限窗口显示的实际 UU 路径。
维护与连接互斥，维护结束前会拒绝新的连接请求；恢复原权限前先验证 VPN 已断开。
只处理自动发现且含有效网易签名主程序、目录拥有者和上层目录安全的安装，将 Users/Authenticated Users 两类明确额外的“修改”授权收紧为“读取和执行”。
不处理任意其他权限、不修改程序文件、不停止 UU。无法安全处理的安装继续保持拦截。
修复前备份目录及现有子项的访问权限，修复失败时尝试自动恢复；若自动恢复无法验证，保留备份并报告失败。
普通用户写入安装目录或 UU 自动更新可能受影响；先确认真实 UU 会话，再试 VPN 连接。
如有问题，点击“恢复 UU 权限（UAC）”；该操作先断开 VPN 再恢复原权限，连接检查可能再次拦截。
如 UU 或管理员在此后修改过权限，恢复操作会拒绝覆盖这些变化，请向维护者提供诊断。
权限备份位于本机受保护的 ProgramData\OracleProxy\uu-permissions-backup.json，不含密码或密钥；卸载时保留此备份以便排障。

紧急恢复
异常时普通应用可能继续被阻断，这是连接保护的一部分。
在原便携目录打开 OracleProxy.exe，点击“恢复直连（UAC）”并确认；该操作关闭自动连接并保留可用密钥。
如果界面不可用，可在本机管理员终端执行同一目录的 OracleProxy.exe --recover。
不要删除服务、加密状态文件或手动关闭系统防火墙来代替恢复。

升级与卸载
升级：完整解压新版，运行新版界面的“安装 / 升级服务”；启动失败自动恢复旧服务文件，账号密钥保留。
卸载：点击“卸载”，确认后恢复直连并删除本产品服务、本机密钥和运行缓存。
服务器仍保留设备历史和用量；如需释放设备名额，请联系管理员撤销旧设备。
首次 UAC 安装后的系统文件存放于 Program Files，便携目录可以移动，但不能只复制单个 EXE。

打开界面后可后台预备加密通道；预备阶段不启用 TUN 接管、不修改普通应用路由，普通应用仍然直连。界面会明确显示“快速连接已就绪”，点击后才启用防泄漏和 VPN。首次使用、网络变化及通道失败时仍可能等待。正常关闭界面会立即结束预备通道。

断开后结束 TUN 会话、清除网卡地址、接管路由、DNS 配置和防泄漏规则，已验证的加密通道和无地址、无接管路由的休眠网卡短暂保留用于快速重连；普通应用恢复直连。退出账号或预备超时会停止通道。每个物理网络中失败的通道暂记五分钟，网络变化会清空记录并重新首选 UDP；不会为了重连每次重新等待已失败的 UDP。首次启动尚未预备完成时，仍需实际握手与出口核验，不能保证一秒。诊断 click_to_ready_ms 为点击到已验证可用的完整时间，connect_switch_ms 仅为服务切换操作时间。

rc8：修复预备连接时文字与按钮闪烁；状态轮询不再覆盖中间提示，轮询期间的连接点击会排队执行。原生 UDP 的端口、开始阶段、出口探测结果和失败次数会保留在“连接诊断”的 native_udp 字段中，即使已回退到 QUIC 也可查看。这些字段不等同于 WireGuard 握手证明；只有出口实测通过才报告已连接。
原生 WireGuard UDP 改用面向实际 IPv4 Peer 的已连接 UDP socket，统一物理网卡选择路径，避免通配双栈监听器在不同 Windows 网络下的选择差异；不添加 QUIC/TLS 封装。是否解决具体网络不可达仍以实机握手与出口验证为准。

rc9 连接方式
可选择“自动（UDP 优先）”“WireGuard / UDP”“QUIC / HTTP/3”；已连接时先断开再切换。HTTPS 只在所选 UDP 通道失败时自动兜底，界面始终显示实际传输方式，不能把兜底成功当作 UDP/HTTP3 成功。
原生 WireGuard 使用一个加密设备，首选51820；若未收到回复，下一份新握手尝试服务器广告的UDP443兼容端口；不会运行两个同密钥的隧道，也不会把原生UDP伪装成HTTP3。QUIC使用标准h3/Extended CONNECT-UDP和HTTP Datagrams，仅允许固定WireGuard目标。
界面意外退出后的未连接预备通道最多保留五分钟，仍不接管普通应用；正常关闭则立即停止。已验证的通道选择提示经过DPAPI保护并绑定物理网络，短期用于重启后选路；它不代替新进程的出口验证。
Oracle管理网站经VPN隧道访问；SYSTEM服务和核心的控制/承载连接固定绑定物理网卡，普通应用仍受防泄漏保护。

rc10：修复双端口复制握手导致备用端口被同一服务器防重放规则拒绝的问题。首次主端口回复丢失时需等待 WireGuard 自身的新握手重试；不承诺首次冷连接一秒。出口验证成功的原生 UDP 端口按物理网络短期记忆，后续核心启动可优先使用，缓存不代替新的出口验证。
预备阶段提前创建本进程持有的休眠网卡，不配置地址、接管路由、DNS 或数据会话；普通应用继续直连。点击连接后才配置并授权隧道，避免把首次 Windows 网卡创建耗时留到点击之后。核心退出时关闭其持有的网卡句柄，不收养其他进程的同名网卡。
收到当前核心的 WireGuard 握手回复后，正在进行的 HTTP 出口核验最多保留至总计12秒，避免3秒取消重来导致错误回退。只有 HTTP/3 通道建立不触发延期，仍必须验证 Oracle 出口 IP。

rc11：正常关闭窗口通过已认证的系统服务执行固定退出操作，停止核心、核验隧道清理、保存断开状态后取消本产品保护。只有收到安全退出确认才关闭界面；失败时保留窗口和恢复指引。未安装服务时可直接关闭。单独断开仍保留快速重连，意外崩溃继续保护。
原生 UDP 诊断增加按51820/443区分的握手发出、回复接收、无效/过期回复、数值 socket 错误计数，回退后保留失败尝试证据。计数每类最多记录32条，不导出报文、密钥或原始日志；收到形状匹配的回复不代替密码学认证和出口验证。client_handshake_reply 仅表示当前核心收到回复，回退到HTTP/3后的true不代表此前原生UDP成功。MetaWise的原生UDP问题仍待实机验收。

rc11协议重试：显式选择UDP或HTTP/3后，新的连接会重新尝试所选协议，不复用上次回退至其他协议的预备核心；在下拉框再次选择相同项目也会触发重新探测。自动模式保留已验证备用通道的快速重连。协议选择仍有受限网络下的自动兜底，实际协议继续明确显示。

rc12：断开时若保留的休眠网卡未通过地址和路由审计，停止自有核心并核验网卡已彻底移除，再保存断开状态及取消保护。不能完成清理时继续保护，不放宽原有审计。恢复状态不再被后台轮询覆盖为普通等待连接。重新选择协议后清除上一轮连接计时，避免把旧计时误认为本次结果。MetaWise 原生 UDP 回包问题仍待定位，本次清理修复不代表原生 UDP 实机验收通过。

rc13：出口请求即使底层 HTTP 操作不响应取消，也受独立等待期限限制；超时后释放该次探测客户端。当前核心收到 WireGuard 回复时仍最多保留至12秒，不能仅凭HTTP/3承载握手延长期限。QUIC TLS 失败只导出固定超时/证书/其他类别，不导出原始错误或令牌。此修复不保证所有冷启动都在一秒内完成。
诊断与测试新增“原生 UDP 8443 测试”：仅在断开时选择，再点击连接。只向服务器已公布的固定8443端口发送原生WireGuard，不包装为QUIC；仍需实际出口验证，失败可自动兜底。正常“WireGuard / UDP”继续先51820再443。重新选择正常协议会退出8443测试。MetaWise原生UDP仍须实机确认，不把QUIC/HTTPS成功算作原生UDP成功。
