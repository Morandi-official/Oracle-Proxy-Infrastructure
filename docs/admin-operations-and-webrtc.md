# 设备、出站保护、审计与 WebRTC

日常设备：创建用户账号后，由用户在Windows客户端确认归属，设备自动进入管理表。无需手工新建Peer。Peer是设备的加密隧道身份。表格“管理”同时打开识别码、接入说明和编辑区，可重命名、调整归属、撤销。换归属仍需新用户在客户端确认；撤销永久停用该密钥、释放名额，保留用量。高级手工公钥入口供外部WireGuard设备使用，不会生成或显示客户端私钥。

官方余额：只读Usage API将历史完整UTC日与今天已完成UTC小时分开查询，避免整月小时范围被API拒绝；小时查询仍受限时明确退回日级截止，每10分钟刷新；官方入账仍可能滞后。界面区分最近查询、用量最后变化、请求的账期截止。查询成功而金额不变可能是Oracle未新增记账，不是实时余额保证。原来按完整UTC日查询导致同一天一直使用相同截止，现已改进。

VPN预算：未校准时显示保守参考，不作为内核放行依据。参考从已验证官方用量按较大的二进制GB扣减，再把本月已采集的全部VNIC出站计入一次，减去配置的额度与安全余量；有意重复扣减以保守覆盖未入账尾部，不把不同单位冒称等价。首次在“历史用量处理”选官方保守校准，核对账期/安全余量并勾选确认，再保存；需要总量阻断时同时勾选启用。之后保留基线即可。也可手工输入核对后的用量。启用后达到阈值或采集缺口会停止全部VPN设备；管理后台和系统流量仍可能消耗额度。新月/缺口需重新校准。此机制不能承诺Oracle账单绝不超额，特别是采集前尚未入账的历史流量；安全余量须覆盖它。部署不自动启用保护或重设用户配额。

审计只展示最新10条，历史不删除。用户频次按近24小时的登录、确认、退出、客户端自报状态变化统计；每5秒的轮询不计数。状态变化为上报元数据，不是请求总量或收费依据。

WebRTC：全局TUN与WFP应使普通浏览器的STUN经Oracle或在故障时被阻断；UU有已核验直连例外。VPN不能阻止浏览器生成本地ICE候选，媒体权限、扩展和浏览器设置可能使内网地址暴露给脚本。公开检查页/ privacy-check/仅在点击后调用RTCPeerConnection，向固定Cloudflare/Google STUN发送少量请求，不请求媒体权限、不上传候选结果。无STUN响应必须标记不确定，不当作无泄漏证据。浏览器设置建议在页内说明，不静默改全局浏览器策略或破坏通话。Windows云端验收会启动独立临时Edge配置，通过真实RTCPeerConnection验证STUN公网候选为Oracle出口，不复用用户浏览器数据。
