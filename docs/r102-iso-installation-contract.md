# R102 — policy-only, ephemeral Windows evaluation installation answer

R99 did not prove native Windows kernel boot from Microsoft's official Evaluation VHD despite 456–458 genuine System.evtx records, verified EFI/BCD and QMP disk attachment. R101 independently verifies authentic Microsoft's Evaluation Center ISO media. This R102 stage **only prepares a bounded answer-file generator** for a future fresh, isolated Windows Server 2025 Standard Evaluation (Desktop Experience) QEMU/KVM trial and does **not** install Windows.

Source `lab/cloud-windows-r102/ephemeral_windows_answer.py` constructs a Microsoft Windows unattended XML specifying only: English locale, UEFI/GPT disk **0** with 260MiB EFI / 16MiB MSR / remaining NTFS OS partition **3**, independently reviewed Microsoft WIM image index, installation EULA, UTC timezone and a freshly generated one-job Administrator password. It never contains first-logon scripts, command execution, Windows security bypass, TPM/secure-boot bypass, system proxy, WFP, VPN, key material, other disks, network configuration, domain membership, product key, or use of the user's Windows device.

**Release/identity caveats:**
- The generator does not establish which `install.wim` index corresponds to the approved official edition; a future CI must first inspect the genuine official ISO and independently prove the edition+index pairing. Caller-provided strings or manifest claims do not establish media authenticity.
- An unattended answer file includes an ephemeral Administrator secret in plain text during **guest installation only**. Future authorized execution must create it under the exact disposable GitHub Runner temp path with permission 0600, never commit or log it, attach it only to isolated host-controlled guest media, and erase it plus all virtual disks at exit. The guest must have **no public NIC**.
- Windows Server Evaluation has its own Microsoft usage and 180-day time-limit conditions. The user authorized only the cloud experiment on existing public GitHub standard free runner, not a paid Microsoft license or public deployment.
- Answer file XML does not establish a successful guest OS boot. The independent Windows kernel and EventLog boot record gate remains mandatory, plus host-side reset/overlay restore, driver trust and WFP/IPv4/IPv6/DNS tests before anything may be considered an actual VPN test. No migration of WireSock/UU or production Oracle settings is permitted.

R83 native field hard-denial and `UnavailableProductionKernel` remain unchanged; GA issue #34 remains OPEN. This PR is an incremental build-time review tool, not a signed VPN installer or product.
