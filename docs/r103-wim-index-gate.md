# R103 — Microsoft evaluation Windows ISO edition/architecture identity gate

R101 validated the real Microsoft Windows Server 2025 Evaluation Center ISO via HTTPS and confirmed UEFI x64, Windows Setup `boot.wim`, and `install.wim` (or ESD) were present using the standard FREE public-repository Linux runner. R102 safely creates a disposable GPT/UEFI Windows Server 2025 Standard Evaluation Desktop Experience answer file with ephemeral per-run Administrator password. **The missing link is verifying the exact install image index from the genuine media**, not guessing that Standard/Desktop is index 2.

The R103 pure standard-library tool reads only the **bounded raw WIM XML resource**, e.g. extracted with Ubuntu `wimlib-imagex info /path/to/sources/install.wim --extract-xml=/tmp/wim.xml` from a strictly read-only mounted official ISO. It requires precisely one image whose `DISPLAYNAME` equals `Windows Server 2025 Standard Evaluation (Desktop Experience)`, `WINDOWS/EDITIONID` is `ServerStandardEval` or `ServerStandard`, `WINDOWS/ARCH` is AMD64 (`9`), and whose 1-based `IMAGE INDEX` is distinct and between 1 and 8. It refuses ambiguous duplicates, missing fields, retail/Datacenter/Core/ARM variants and files exceeding 1MiB. Its only returned payload is the numeric index with an explicit **metadata-only nonauthorization** disclaimer.

**Security:** XML metadata is NOT a signature or Microsoft trust proof. A later CI must repeat R101 HTTPS/authentic evaluation media verification and extract the index in the same disposable isolated cloud job. The source-only R103 tests use synthetic UTF-16 WIM XML; no ISO is downloaded again, no Windows is installed or booted, no drivers, no guest NIC, no WireGuardNT/WFP/route/DNS/UU or policy change, no payment or privileged host access, no user Windows/Oracle action. The code cannot override R83 or GA Issue #34. Real install and native OS/WFP testing remain separately gated.
