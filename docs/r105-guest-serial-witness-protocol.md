# R105 — read-only future isolated guest serial challenge, NOT Windows boot attestation

The user authorized real WireGuardNT/WFP testing only inside a recoverable free cloud Windows VM. R97 proved Linux host-owned external QEMU disk rollback; R100 proved host TAP isolation; R99's official prepared VHD could not corroborate kernel/EVTX host-clock witness. R101–R103 passed genuine Microsoft Server Evaluation ISO and offline installation metadata checks. R104 currently attempts one real ISO installation with no guest NIC. **Do not deploy the R105 agent until R104's actual guest kernel boot and recovery safety gate passes.**

R105 implements only a bounded COM1 one-shot responder for a future authorized disposable Windows guest. It accepts an exact uppercase 256-bit nonce challenge and prints only the nonce, Windows build number and whether its token SID is `S-1-5-18` (LocalSystem). It **never** accepts an arbitrary command, tunnel key, DNS, route, WFP filter, shell or script. On any wrong flag, lower privilege, invalid nonce or unavailable Windows COM1 port it exits nonzero without retry or modifying the OS. The host independently checks nonce echo, field bounds, SYSTEM token claim and a minimum supported Windows build. No credentials, usernames, hostnames, addresses, packet captures or secrets appear in output.

This is **not cryptographic attestation**: a compromised or substituted guest process could forge the claim, and a separate host-origin event-log/kernel startup witness plus physical network packet observer is still mandatory. `release_approved_from_serial()` always returns false. No network access, unsigned installer distribution, Windows driver or WFP action is included.

The CI job does pure Python adversarial tests and compiles the C# Windows program in an ordinary disposable GitHub hosted Windows runner. It invokes `--self-test` only. In particular it does NOT use `--serial-once`, open COM1, register a service, modify the Windows execution policy, install an unsigned executable on a user's device or change Oracle/OCI. No paid Runner, private artifact, GitHub cache, signing key or new cloud.

Even after R104 succeeds, a *future separate CI-specific installer/launch design* must prove approved authentic executable provenance, exact isolated VM identity, guest OS security policy acceptance and external host rollback before staging R105 in the guest. R83 field native connection refusal and GA Issue #34 OPEN are unchanged. This protocol is merely preparatory infrastructure for an independently observable Windows guest; it cannot by itself deliver a WireSock replacement.
