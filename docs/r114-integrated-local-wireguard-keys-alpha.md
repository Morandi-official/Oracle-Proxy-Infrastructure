# R114 — Oracle Proxy built-in **offline** WireGuard X25519 test-key generator

R114 adds an optional local-only **生成本机测试密钥（离线）** button to the standalone Windows x64 GUI. This operation runs as the current Windows account and does **not** require the user to download/install official WireGuard, install a Windows service, change routes, alter firewall/WFP, open a socket, or connect to Oracle/Aliyun/LittleEmpire. GitHub Windows CI uses synthetic test keys only; **no real user key or configuration is part of the package or logs**.

## Required test steps for user

1. Download the **R114** unsigned developer artifact only from the project's GitHub Actions CI page; unzip the outer Actions artifact ZIP, then the inner product ZIP. Read this file and both WireGuard licenses plus `BOUNCYCASTLE_MIT_LICENSE.md`. Keep `OracleProxy.WgAlpha.exe`, `tunnel.dll`, and `wireguard.dll` in their original shared directory. If Windows blocks an unsigned binary, **do not disable security protections** to run it.
2. With the current network and any existing WireSock/UU unchanged, launch `OracleProxy.WgAlpha.exe` normally (**no elevation needed merely to generate keys**). Do **not** click `选择配置并连接（实验）`.
3. Click **生成本机测试密钥（离线）**. Confirm the **plaintext-private-key-in-restricted-local-folder** warning. Select a controlled **local, nonsynced** folder, e.g. a private local test folder under the current user's profile. Avoid public desktops, OneDrive, synced folders, network shares, unknown junctions and removable media.
4. Oracle Proxy creates a **new uniquely named subfolder** `OracleProxyAlphaKeys-<GUID>` and stores two different files there:
   - `OracleProxyAlphaTest.privatekey` — 32-byte clamped Curve25519 private scalar, base64 text. **Never send, paste into chat, commit, upload or disclose this file to anyone.** Access is explicitly limited by Windows NTFS ACLs to the current Windows identity and LocalSystem.
   - `OracleProxyAlphaTest.publickey` — matching base64 WireGuard public key; safe to share with a trusted *dedicated test server administrator*, **not** a secret.
   The GUI displays **only** the public key and local directory location; secret input/output, clipboard history and test report are never populated with the private key.
5. Do not rename or overwrite the existing `OracleProxyAlphaTest.conf.template.txt` until a separate non-production WireGuard test server is ready. Later paste the private base64 **locally**, by yourself, into a **new** `OracleProxyAlphaTest.conf` under `[Interface] PrivateKey`; the remote server's independent public key, nonconflicting interface address, server IP/UDP port and narrow /32 `AllowedIPs` must come from that authorized test server. The generator **does not write .conf files**, update the existing template or invoke the real tunnel.
6. For now export `OracleProxy-R114-AlphaReport.json` only if needed. It reports `local_offline_keygen_result` as a categorical result and does not include keys. Full handshake, routing, DNS, WFP fail-close, safe recovery, Internet egress and UU compatibility remain **NOT_TESTED** in this GUI.

## Technical key/permission guarantees and known limits

- The app uses Windows `RandomNumberGenerator.Fill` to obtain 32 entropy bytes, applies canonical WireGuard RFC 7748 private-key clamping, and uses a pinned `BouncyCastle.Cryptography` v2.7.0 managed X25519 implementation to derive the public key. No wireguard.exe or downloaded CLI is required. CI self-test includes the RFC 7748 Alice public vector. Use official library MIT license notice.
- A new, previously absent output directory is created under user-chosen *local* existing parent, with a **noninheriting NTFS ACL** granting access to the current Windows SID and LocalSystem. The two files are exclusively created, never overwritten, and receive protected NTFS ACLs verified before success. The parent path is rejected if it or its ancestors are reparse points (junctions, symlinks); UNC/network paths and volume roots are rejected. Access control does not protect against malware **running as the same user**, an administrator, OS backups, endpoint software, or unrecognized cloud sync; choose a truly offline, nonsynced folder. Private scalar and public derivation buffers are zeroed after use; managed base64 strings are minimized but .NET cannot guarantee immediate erasure.
- The public/secret pair is generated together; user has to preserve its output folder. Repeated presses create **new unrelated pairs**, not recover or replace existing keys. Future server must use the corresponding public key.
- R114's elevated native service remains limited to the R113 separately verified local SCM start-stop and protected narrow-route trials. No distributed R114 binary contains CI-only privileged trial entrypoints. A successful offline keygen is not proof of working Internet proxy. The remote server and keys are never part of GitHub CI.
- Signed publisher installer, WFP full-device kill switch, crash/reboot and UU continuity remain unreleased and unverified; do not replace working WireSock or use on a remotely accessible critical Windows system.
