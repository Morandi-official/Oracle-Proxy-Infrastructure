# rc23 客户端响应与 UU 维护修复

本轮区分两台电脑的报告：MetaWise 上的界面卡住、退出无响应与恢复按钮裁切；另一台电脑的 UU 4.44 安装目录对普通用户可写，连接在信任核验阶段被拒绝，隧道尚未启动。这不是一次 UDP 握手失败。UU 信任标准、发布者校验、原生防泄漏规则及管理员命令范围保持原样。

## 请求和退出

普通状态轮询只读 `Status`；窗口初次读取到已登记且断开的设备后，只发起一次有限预热。预热核验失败退避 30 秒，避免每 200 毫秒重复扫描。断开可保留已审计的 standby，但不会在它退出或换通道后未经许可新建核心；显式连接仍允许恢复。

界面请求与退出有等待上限。超时表示结果未知，不表示已取消服务端操作。排队但尚未获准执行的管道命令会在客户端断开或排队取消时撤销；已经执行的命令仍完整串行完成。再次修改状态或退出前，界面需取得服务的最新状态作为顺序屏障。正常安全退出仍要求服务确认已断开、连接意图关闭且核心停止；超时保留窗口与恢复入口。管道身份验证、SCM PID 绑定和帧限制保留。

## 界面和权限维护

恢复直连入口固定在右侧底栏，不受卡片展开、滚动或请求等待状态影响。按钮换行按实际宽度计算卡片高度。

UU 目录可写时显示实际拒绝路径，引导显式 UAC 维护。修复成功后自动重新识别；取消、失败或超时不会误报成功，也不自动连接。维护超时只结束界面等待，不强杀正在执行的权限备份或回滚事务。

现有权限修复仅支持已识别、签名通过、父目录安全且符合既有授权模式的 UU 安装目录。`UU_REPAIR_NO_MATCH` 时不改权限，不会扩大到共享父目录或跳过信任核验。

## 交付与验收要求

便携 ZIP 与安装 EXE 继续使用自包含 .NET 10 LTS，SDK 10.0.403、运行时 10.0.14。不得发布未通过主线真实 Oracle 验收的构建。

新增 Windows 回归覆盖实际窗口尺寸、折叠组合、恢复按钮可见与命中区域、超时消息泵、迟到响应、退出确认、管道断线、排队取消和预热退避。原有 SYSTEM/DPAPI、UU 签名与 ACL 阴性、低 MTU 双栈、三通道与安装卸载验收继续保留。物理用户电脑的权限配置不由云端测试代替。
