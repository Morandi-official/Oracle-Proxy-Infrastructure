# rc23 客户端响应与 UU 维护修复

本轮区分两台电脑的报告：MetaWise 上的界面卡住、退出无响应与恢复按钮裁切；另一台电脑的 UU 4.44 安装目录对普通用户可写，连接在信任核验阶段被拒绝，隧道尚未启动。这不是一次 UDP 握手失败。UU 信任标准、发布者校验、原生防泄漏规则及管理员命令范围保持原样。

## 请求和退出

普通状态轮询只读 `Status`；窗口初次读取到已登记且断开的设备后，只发起一次有限预热。预热核验失败退避 30 秒，避免每 200 毫秒重复扫描。断开可保留已审计的 standby，但不会在它退出或换通道后未经许可新建核心；显式连接仍允许恢复。

界面请求与退出有等待上限。超时表示结果未知，不表示已取消服务端操作。排队但尚未获准执行的管道命令会在客户端断开或排队取消时撤销；已经执行的命令仍完整串行完成。再次修改状态或退出前，界面需取得服务的最新状态作为顺序屏障。正常安全退出仍要求服务确认已断开、连接意图关闭且核心停止；超时保留窗口与恢复入口。管道身份验证、SCM PID 绑定和帧限制保留。

## 界面和权限维护

恢复直连入口固定在右侧底栏，不受卡片展开、滚动或请求等待状态影响。按钮换行按实际宽度计算卡片高度。

UU 目录可写时显示实际拒绝路径，引导显式 UAC 维护。修复成功后自动重新识别；取消、失败或超时不会误报成功，也不自动连接。维护超时只结束界面等待，不强杀正在执行的权限备份或回滚事务。

常规修复保留原有范围。对于非系统固定 NTFS 盘的标准 `Program Files[ (x86)]/(Netease|UUNetease)/GameViewer` 布局，提供保留位置的显式路径保护：先验证真正的网易签名、现有可信拥有者、卷及文件身份、完整既有授权模式，再展示两级必要父目录与 UU 根的保护预览。不会更改安装位置、拥有者或盘根权限。

共享父目录只收紧作用于自身的已知普通用户 Modify 授权，保留对子目录的原继承策略；目录使用 Windows 文档规定不传播给子项的 MAXIMUM_ALLOWED 句柄，任何失败都不退回会传播的写法。UU 子树逐对象冻结继承并保留副本，再收紧已知 Modify；所有目标均在首写前锁定、验证并生成版本 2 备份。其他软件子树不纳入写入或回滚。普通用户直接在这些父层新建或整体替换软件目录可能需要管理员授权，这是预览中明示的影响。

版本 2 备份严格限定角色和派生路径，核验自身权限、对象与卷身份、原始及预期 ACL、来源父级依赖，并逐对象比较后恢复。已有版本 1 备份保持原范围。文件或目录占用时在首写前拒绝；程序不自动关闭 UU，允许在可本地操作的情况下退出 UU 后重试。未知授权、拥有者、别名或外部更改不会被强行覆盖。

成功签名缓存按完整文件对象身份共享，固定 60 秒到期，命中不续期；每条路径的拥有者、ACL、重解析点与文件身份仍逐次核验。多个硬链接不会重复验证同一对象，修改、替换和相同修改时间的篡改仍触发重新核验。

## 交付与验收要求

便携 ZIP 与安装 EXE 继续使用自包含 .NET 10 LTS，SDK 10.0.403、运行时 10.0.14。不得发布未通过主线真实 Oracle 验收的构建。

新增 Windows 回归覆盖实际窗口尺寸、折叠组合、恢复按钮可见与命中区域、超时消息泵、迟到响应、退出确认、管道断线、排队取消和预热退避。独立 Windows 2022/2025 门禁使用专属临时 NTFS VHD，要求其他软件子树的原生安全描述符不变、普通用户仍可写其既有子目录、路径不能被替换，以及精确回滚与故障恢复。官方 UU 文件仅验签，从不执行。原有 SYSTEM/DPAPI、UU 签名与 ACL 阴性、低 MTU 双栈、三通道与安装卸载验收继续保留。物理用户电脑的权限配置不由云端测试代替。
