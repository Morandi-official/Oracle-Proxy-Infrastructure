# UU 原位置维护与运行数据

rc24 的自定义盘原位置修复错误地将普通账号创建的 config/log 数据当作程序对象，导致 OWNER_REFUSED。高级修复现在只纳管程序树，固定根下 config/log 数据目录不遍历、不锁定、不写权限或拥有者，也不成为新事务的回滚目标；原生 MAXIMUM_ALLOWED 目录写入阻止对数据和同级软件的继承传播。盘根不写入，程序对象的拥有者、ACL、签名、对象身份和事务比较仍核验。原版本备份仍按其原记录验证与恢复。

config/log 中的 EXE 即使有网易签名，也不作为可直连的 UU 程序，且不能用作原位置修复的主程序验签凭据。固定数据根本身是重解析链接时拒绝维护。程序树内未知拥有者仍拒绝；提示现在包含本机路径和拥有者 SID，缺少 DACL 使用独立代码。

Windows 原生回归创建普通账号拥有的 config/popup、streamer、log/client 等目录和数据。要求 ACL/owner/文件内容不变、修复后普通用户仍可创建文件/子目录，活跃日志写句柄不阻止程序维护；数据 EXE 永不获信任。程序对象占用、未知拥有者、仅数据目录存在已签名主程序、数据根链接、故障及外部修改仍须首写前拒绝或精确回滚。验收成功的主线构建才可发布 rc25。
