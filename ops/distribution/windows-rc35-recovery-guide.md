# rc35：恢复直连与其他代理兼容性

## 本轮修复的两个错误

- `RECOVERY_TUN_OWNER_GUARD_REQUIRED`：rc34 的 UAC 恢复将“已断开但保留预备网卡”的状态送入了要求保护已启用的恢复路径。
- `OWNED_TUNNEL_REMOVAL_NOT_VERIFIED`：主服务重启时只等待网卡消失，没有调用已有的归属校验恢复，可能导致服务反复退出，窗口无法获得新状态。

rc35 的服务启动和 UAC 恢复共同采用已有的保护/断开状态选择器。仍须验证网卡归属记录、创建进程身份及退出、持久化状态，以及本机 IP、路由、DNS 条件。不会因为网卡名字相同就删除它，也不会清空其他软件的规则。

恢复辅助服务结束后，即使恢复失败，也恢复主控制服务以供重新诊断。窗口跟踪管理员授权及恢复子进程结果，取消授权和失败也会重新读取状态。恢复尚未结束时不会重复启动恢复或将网络冒认为直连。

## 其他代理软件

同机存在其他代理不等于已经发生冲突。浏览器的系统代理或 PAC、仍运行的本地代理端口，以及其他 VPN 的路由或过滤规则，均可能影响访问。rc35 的“连接诊断”会只读显示：

- GUI 当前用户的系统代理启用标志、是否配置 PAC。
- 配置中的本地代理端口，以及哪些端口有监听。
- 其他活动 VPN 网卡候选数量；这是候选信息，不是冲突定论。
- 控制服务当前状态、上次客户端快照的年龄，避免把旧快照当成实时结果。

不输出代理密码、PAC URL、远端代理主机或网卡名称。不擅自结束其他进程、修改系统代理、禁用其他网卡或删除第三方规则。不通过给浏览器/其他代理添加直连白名单绕开保护。

如果浏览器仍报 ERR_NETWORK_ACCESS_DENIED，先提供新版本的连接诊断；只有实际状态和设置支持时才做针对性调整。不要批量关闭防火墙，也不要重复删除或重装网卡。

## 升级

使用 GitHub 发布的 setup.exe，或解压完整便携 ZIP 后启动 Proxy.exe 并允许服务升级。不要只替换内部 DLL/EXE。账号、登记设备和恢复归属记录保留，不修改 OCI 绑定或 DNS。
